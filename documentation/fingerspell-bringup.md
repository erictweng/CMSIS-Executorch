# Fingerspell on the Alif Ensemble E8 DevKit: bring-up report

Status (2026-10-17): **the Fingerspell 24-letter model runs on the DevKit-E8's
Ethos-U85 and prints `Test_result: PASS` on the UART.** This is milestone S1
of [erictweng/fingerspell](https://github.com/erictweng/fingerspell) (private):
the model on the board, classifying a test crop built into the firmware.
Camera input comes next.

## What runs

| Item | Value |
|---|---|
| Board | Alif Ensemble E8 DevKit (`DevKit-E8`), core M55_HP, device `AE822FA0E5597LS0` |
| NPU | Ethos-U85-256, Vela `Ethos_U85_SRAM_MRAM` / `Shared_Sram` |
| Model | MobileNetV2-0.5, 128x128x3 NHWC input, 24 logits (`ABCDEFGHIKLMNOPQRSTUVWXY`, no J/Z) |
| Quantization | int8, 300 real calibration crops (`model/calib_128.npy`) |
| Program (`.pte`) | 896,016 bytes, 55/55 operators on the NPU, 0 on the CPU |
| NPU SRAM | 321 KiB (Vela) |
| Firmware image | Code 132,960 B, RO data 957,968 B, RW 832 B, ZI 3,532,076 B |
| Test | Built-in held-out crop of the letter **B** (`src/test_image.h`) |
| Result | `Top-3: B ...  (expected B)` and `Test_result: PASS` |

## How to reproduce (macOS)

Tools come from `vcpkg-configuration.json` through Arm Tools / vcpkg and are installed in
`~/.vcpkg/artifacts/2139c4c6/`: CMSIS-Toolbox 2.15.0, Arm Compiler 6.24 (MDK Community
license), CMake 4.2.1, Ninja 1.13.2. Packs are in `~/.cache/arm/packs`. SEGGER J-Link
V9.86a is installed, and Alif SETOOLS is in `~/Documents/app-release-exec-macos`.

```bash
# 0. Tool environment for a plain shell (CMSIS-Toolbox 2.15.0, NOT VS Code's bundled 2.13)
T=~/.vcpkg/artifacts/2139c4c6
export PATH=$T/tools.open.cmsis.pack.cmsis.toolbox/2.15.0/bin:$T/tools.kitware.cmake/4.2.1/bin:$T/tools.ninja.build.ninja/1.13.2:$PATH
export AC6_TOOLCHAIN_6_24_0=$T/compilers.arm.armclang/6.24.0/bin

# 1. Packs + cmsis-executorch.cbuild-mlops.yml for the active target
cbuild setup cmsis-executorch.csolution.yml --active DevKit-E8 --packs

# 2. Python venv (once; Python 3.10-3.13, the system python3 is 3.9)
./setup_venv.sh --uv --python 3.12

# 3. Export the model into the AI layer (~1 min)
.venv/bin/python create_ai_layer.py cmsis-executorch.cbuild-mlops.yml

# 4. Build
cbuild cmsis-executorch.csolution.yml --active DevKit-E8

# 5. Flash over the on-board J-Link (PRG USB) and start
printf 'connect\nh\nloadfile "out/cmsis-executorch/DevKit-E8/Debug/cmsis-executorch.hex"\nr\ng\nqc\n' > /tmp/load.jlink
JLinkExe -device AE822FA0E5597LS0_M55_HP -if SWD -speed 4000 -autoconnect 1 -NoGui 1 -CommandFile /tmp/load.jlink
```

Serial output: SW4 on **UART4**, `/dev/cu.usbmodem0012195786141` at 115200 8N1
(VS Code Serial Monitor). Open the port before the reset: the app prints once.

One-time board prep (already done on this board): with SW4 on **SEUART**, run the VS Code task
*Alif: Install M55_HP debug stubs (DevKit-E8, single core configuration)*, then set SW4 back
to UART4. That task writes the boot table that starts the M55_HP from `0x80200000`.

## Gotchas found on the way

1. **VS Code builds fail with `csolution.yml:120:3 schema check failed`.** CMSIS Solution
   extension 1.66 uses its bundled CMSIS-Toolbox 2.13, which doesn't know the `mlops:`
   node (added in 2.15). Newer extensions (1.67 and later) need VS Code 1.108.1 or newer.
   Workaround: build from a terminal with 2.15.0 as in step 0, or update VS Code (move
   it out of `~/Downloads` first, because macOS App Translocation blocks self-update).
2. **`get_methods() got an unexpected keyword argument 'input_shape'`.**
   `cmsis-executorch.cbuild-mlops.yml` is stale after switching branches. Rerun
   `cbuild setup` before `create_ai_layer.py`.
3. **The VS Code tasks are missing from Run Task.** The repo keeps them in `.vscode.d/tasks.json`.
   Copy that file to `.vscode/tasks.json` (git ignores it).
4. **The plain "Setup Python virtual environment" task fails with Python 3.9.** Use the
   `(uv)` variant with `3.12`.
5. **Blank console after Run.** The image had never been loaded, and the core was still
   running the debug stub (reset vector `0x80200989` instead of the app's `Reset_Handler`).
   Load the image as in step 5.
6. **The core sits in HardFault after the test (HFSR = `0x80000000`, DEBUGEVT).** This is
   expected. When `main()` returns, `_sys_exit` executes a semihosting `BKPT 0xAB`, which
   faults when no debugger is attached. All output has been printed by then. A camera
   loop should not return from `main()`.
7. **J-Link: keep SWD.** JTAG makes the generated load task block on a prompt.

## Display (DevKit-E8 LCD)

The 4.3" LCD (ILI9806E, 480x800, J21) shows what the camera sees and what the model
thinks, every frame: the 128x128 hand-box crop scaled 3x (a mirror image), the top
letter in big type with its probability and a bar (green from the decoder's 0.60
commit threshold up), the 2nd/3rd guesses, `CAM/NPU/UI` times and fps, and the
committed text. Code: `src/fs_display.cpp` (`fs_ui_init`, `fs_ui_render` from
`src/fs_api.h`), built for DevKit-E8 only (`FINGERSPELL_LCD`); details in
`board/DevKit-E8/README.md`. The live UART line gains `ui x.xms`:

    X 0.30 U 0.21 M 0.06 | cam 25.0ms pre 1.0ms npu 7.8ms ui 1.9ms | 19.5 fps

Three board fixes came with it (found on `hackathon-pico-faces`): bulk SRAM starts
64 kB above `0x02000000` so the camera ring no longer overwrites the A32 boot stub
the ATOC loads there; everything the NPU and the CDC200 read stays in SRAM0
(`SRAM0_SRAM1_COMBINED 0`, temp pool 1 MB); `main()` cleans and invalidates the
caches first, so a warm reset after a flash does not run stale lines of the
previous image. The stage timings now come from the SoC's 100 MHz REFCLK counter: the M55's DWT
cycle counter only runs while a debugger is attached, so a board that booted on its
own printed `0.0ms`. Tests: `tests/test_display.py` (`FS_HW=1` flashes and checks the
panel message, the `ui` time < 10 ms at >= 15 fps, the frame buffer changing with
the camera, and a warm reset).
